# Architecture — Vibe Stats for macOS

Pure Swift. Zero third-party runtime dependencies. SwiftUI for presentation, AppKit for the menu bar surface, structured concurrency for everything else.

---

## 1. Layering

```
┌──────────────────────────────────────────────────────────────┐
│ App                main.swift · AppDelegate                  │  AppKit
│                    StatusItemController · PopoverController  │
│                    SettingsWindowController · AboutWindow    │
├──────────────────────────────────────────────────────────────┤
│ Presentation       PopoverView · ServiceCard · Settings      │  SwiftUI
│                    VibeIcon (Shape) · animations             │  @Observable VM
├──────────────────────────────────────────────────────────────┤
│ Coordination       MonitorCoordinator (timer, wake, network) │  @MainActor
│                    NotificationDispatcher · SystemObservers  │
├──────────────────────────────────────────────────────────────┤
│ Engine             StatusEngine  ← the port of VStateMonitor │  actor
│                    StatuspageAdapter · GoogleCloudAdapter    │
│                    ComponentMatcher · IncidentNormalizer     │
├──────────────────────────────────────────────────────────────┤
│ Domain             ServiceRegistry · StatusIndicator         │  pure, Sendable
│                    ServiceSnapshot · ComponentState          │  no I/O, no UIKit
│                    Incident · CombinedStatus                 │
├──────────────────────────────────────────────────────────────┤
│ Infrastructure     StatusAPIClient · SnapshotStore           │
│                    Preferences · LaunchAtLogin · HistoryLog  │
└──────────────────────────────────────────────────────────────┘
```

**Dependency rule:** arrows point down only. `Domain` imports nothing but `Foundation`. `Engine` is fully testable with a stubbed `StatusAPIClient` and no clock.

This mirrors the extension's own layering — `services.js` (Domain) / `status-monitor.js` (Engine) / `popup.js` (Presentation) / `background.js` (Coordination) — deliberately, so the parity matrix in specs.md §3 maps file-to-file.

## 2. Platform choices

| Choice | Decision | Why |
|---|---|---|
| Deployment target | **macOS 26.0+** | Liquid Glass materials, Icon Composer app icons, the current SwiftUI surface, and Swift 6.2 concurrency defaults are all used directly. One target, no availability forest |
| Swift | **latest 6.x (6.4 as built), language mode 6** | `SWIFT_STRICT_CONCURRENCY = complete` and `SWIFT_APPROACHABLE_CONCURRENCY = YES` (which brings `nonisolated(nonsending)` by default). Default actor isolation stays **`nonisolated`**, *not* `MainActor` — see §2.1. Data-race safety is checkable here, not aspirational |
| Menu bar surface | **`NSStatusItem` + `NSPopover`**, not `MenuBarExtra` | Needs: custom-drawn animated glyph, badge compositing, distinct left/right click behaviour, precise popover anchoring, and programmatic show-on-notification. `MenuBarExtra` gives up all of it |
| App entry point | **Plain AppKit `main.swift`**, not a SwiftUI `App` | Built as a SwiftUI `App` with a `Settings` scene first, and **the Settings window silently failed to open**: reaching it means sending `showSettingsWindow:`, a selector SwiftUI installs on the responder chain but neither exposes nor documents, and for an accessory app that chain is not reliably in place. `SettingsWindowController` and `AboutWindowController` now own their windows outright. SwiftUI still draws everything; it no longer decides when a window exists |
| Popover contents | **SwiftUI in `NSHostingController`** | Best of both. Surfaces use the system glass materials (`.glassEffect`, `.backgroundExtensionEffect`) rather than hand-rolled blur |
| Project format | **Xcode project generated by a checked-in `project.yml` (XcodeGen)**, or a plain `.xcodeproj` if the generator is unwanted | The build must be reproducible from the repo; a hand-edited pbxproj is not reviewable |
| Toolchain | **Xcode 27.x, pinned in `.xcode-version`** | CI and local builds must agree on the Swift compiler. `make` sets `DEVELOPER_DIR` so no `xcode-select` is required |
| DerivedData | **Outside the repo** (`~/Library/Developer/Xcode/DerivedData/VibeStats-build`) | This checkout lives in an iCloud-synced folder, which stamps `com.apple.FinderInfo` on directories; codesign then fails with *"resource fork, Finder information, or similar detritus not allowed"*. Building out-of-tree avoids it entirely |
| Networking | `URLSession` (ephemeral config) | No dependency, full timeout control |
| Persistence | JSON files in Application Support + `UserDefaults` for settings | Human-inspectable, trivially resettable, no Core Data ceremony for < 1 MB of state |
| Sandbox | On, `com.apple.security.network.client` only | |

### 2.1 Actor isolation default

Swift 6.2 can make `MainActor` the default isolation for a module. This app deliberately **does not** use that, despite being UI-heavy.

The reason is that it is a single module. With `-default-isolation MainActor`, the Domain value types — `StatusIndicator`, `ServiceSnapshot`, `ComponentState` — would become main-actor isolated, and `StatusEngine` (an actor, deliberately off the main thread) could not read their stored properties. Every Domain and Engine type would need an explicit `nonisolated`, which is more annotation than the alternative, and it would put the annotation on the layer that should be isolation-free.

So: **default isolation is `nonisolated`, and the UI is annotated.** In practice the UI annotates itself — `View`, `NSApplicationDelegate`, and every AppKit type are already `@MainActor` — leaving only `MonitorCoordinator`, `StatusItemController`, and `PopoverController` to say so explicitly. The isolation of each type is then visible at its own declaration, which is the property worth having.

If the app is later split into a `VibeStatsKit` module, that module keeps `nonisolated` and the app module can adopt the `MainActor` default.

### 2.2 Build

```
make generate   # project.yml -> VibeStats.xcodeproj (never hand-edit the project)
make build      # universal Debug build, ad-hoc signed WITH the sandbox live
make test       # unit tests
make run        # build, kill any running copy, launch
make release    # Release archive
```

Debug builds are ad-hoc signed rather than unsigned so the App Sandbox and the network entitlement are active during development — building unsigned hides container-path and entitlement problems until release day.

## 3. Domain

Everything here is `Sendable`, value-typed, and free of I/O. This is the direct port of `src/core/services.js`.

```swift
// StatusIndicator.swift

/// The five-level scale. Note `unknown` is deliberately NOT Comparable against
/// the others — see rollUp(_:). Ranking it below .operational is the defect
/// documented in REVIEW.md §3.1.
enum StatusIndicator: String, Codable, Sendable, CaseIterable {
    case unknown, operational, minor, major, critical

    /// Severity ordering for *known* states only.
    var severity: Int {
        switch self {
        case .unknown:     return -1     // sentinel: never wins a comparison
        case .operational: return 0
        case .minor:       return 1
        case .major:       return 2
        case .critical:    return 3
        }
    }

    var title: String {          // ≙ statusLabel()
        switch self {
        case .operational: return "Operational"
        case .minor:       return "Degraded"
        case .major:       return "Partial Outage"
        case .critical:    return "Major Outage"
        case .unknown:     return "Unknown"
        }
    }

    var compactTitle: String {   // ≙ componentStatusText()
        switch self {
        case .operational: return "OK"
        case .minor:       return "DEGRADED"
        case .major:       return "PARTIAL"
        case .critical:    return "OUTAGE"
        case .unknown:     return "UNKNOWN"
        }
    }

    /// ≙ mapComponentStatus() — exact table first, then keyword sniffing so a
    /// new vendor state ("degraded_availability") still registers as a problem.
    init(componentStatus raw: String?) {
        guard let key = raw?.lowercased().trimmingCharacters(in: .whitespaces),
              !key.isEmpty else { self = .unknown; return }
        switch key {
        case "operational":                            self = .operational
        case "under_maintenance", "degraded_performance": self = .minor
        case "partial_outage":                         self = .major
        case "major_outage":                           self = .critical
        default:
            if key.contains("major") || key.contains("critical")   { self = .critical }
            else if key.contains("partial")                        { self = .major }
            else if key.contains("degraded") || key.contains("minor")
                  || key.contains("maintenance")                   { self = .minor }
            else if key.contains("operational") || key == "none"   { self = .operational }
            else                                                   { self = .unknown }
        }
    }

    /// ≙ mapPageIndicator()
    init(pageIndicator raw: String?) { /* none→operational, maintenance→minor, … */ }
}

/// ≙ rollUpStatus(), with REVIEW.md §3.1 fixed.
///
/// Returns .unknown only when EVERY input is unknown. Otherwise returns the
/// worst known state — and the caller is expected to surface `unresolved`
/// separately rather than letting unknowns silently vanish into "operational".
struct RollUp: Sendable {
    let indicator: StatusIndicator
    let unresolved: Int

    init(_ indicators: [StatusIndicator]) {
        let known = indicators.filter { $0 != .unknown }
        unresolved = indicators.count - known.count
        indicator = known.max(by: { $0.severity < $1.severity }) ?? .unknown
    }
}
```

```swift
// ServiceRegistry.swift  — ≙ SERVICES / SERVICE_IDS

struct ServiceDefinition: Identifiable, Sendable {
    let id: ServiceID                 // enum: claude, github, openai, gemini
    let name: String                  // "Claude AI"
    let vendor: String                // "Anthropic"

    let api: ServiceAPI
    let accent: AccentToken           // design token, not a Color (Domain has no SwiftUI)

    case statuspage(base: URL)        // {base}/status.json | components.json | incidents.json
    case googleCloud(incidents: URL)
}

struct ComponentDefinition: Identifiable, Sendable {
    let id: String                    // "claude-code"
    let label: String                 // "Claude Code"
    let exactMatches: [String]        // lowercased
    let patterns: [Regex<AnyRegexOutput>]
    let isPrimary: Bool
}
```

Registry entries are the tables in specs.md §4, transcribed. A test decodes a JSON export of `services.js` and asserts field-by-field equality (specs.md §7.5).

```swift
// Snapshot types — the persisted shape, ≙ the `vstateServices` storage schema

struct ComponentState: Codable, Sendable, Identifiable {
    let id: String
    let label: String
    let isPrimary: Bool
    let matched: Bool
    let matchedName: String?          // the vendor's own component name
    let rawStatus: String?            // the vendor's own status string
    let indicator: StatusIndicator
    let detail: String?
    let provenance: Provenance        // .reported | .derivedFromIncidents  (REVIEW.md §3.10)
}

struct ServiceSnapshot: Codable, Sendable, Identifiable {
    let id: ServiceID
    let name: String
    let indicator: StatusIndicator
    let pageIndicator: StatusIndicator
    let componentsResolved: Int
    let componentsWatched: Int
    let components: [ComponentState]
    let incidents: [Incident]
    let affectedComponents: [String]
    let error: String?
    let checkedAt: Date

    var divergesFromPage: Bool { pageIndicator != indicator }
}

struct CombinedStatus: Codable, Sendable {
    let indicator: StatusIndicator
    let description: String
    let affectedServices: [String]
    let affectedComponents: [String]   // "Claude AI: Claude Code"
    let affectedCount: Int
    let unresolvedCount: Int           // new — makes REVIEW.md §3.1 visible
}

struct Snapshot: Codable, Sendable {
    let services: [ServiceID: ServiceSnapshot]
    let combined: CombinedStatus
    let updatedAt: Date
    let lastSuccessfulCheck: Date?
    let lastError: CheckError?
}
```

## 4. Engine

`StatusEngine` is an `actor`. It is the port of `VStateMonitor` minus everything platform-shaped: no timer, no badge, no storage. It takes a client, returns a `Snapshot`, and is completely deterministic under test.

```swift
actor StatusEngine {
    private let client: StatusAPIClientProtocol
    private let clock: any Clock<Duration>

    /// ≙ checkAllStatuses(). TaskGroup ≙ Promise.allSettled: a thrown error
    /// inside one child degrades that service to .unknown and nothing else.
    func check(services: [ServiceDefinition]) async -> Snapshot {
        var snapshots: [ServiceID: ServiceSnapshot] = [:]
        await withTaskGroup(of: (ServiceID, ServiceSnapshot).self) { group in
            for definition in services {
                group.addTask {
                    do    { return (definition.id, try await self.check(definition)) }
                    catch { return (definition.id, .unknown(definition, error: error)) }
                }
            }
            for await (id, snapshot) in group { snapshots[id] = snapshot }
        }
        return Snapshot(services: snapshots, combined: combine(snapshots), updatedAt: .now, …)
    }
}
```

### 4.1 Statuspage adapter

```swift
// ≙ checkStatuspageService()
// Three independent fetches; each failure is absorbed, matching allSettled.
async let status     = try? client.get(StatusPayload.self,     from: base/"status.json")
async let components = try? client.get(ComponentsPayload.self, from: base/"components.json")
async let incidents  = try? client.get(IncidentsPayload.self,  from: base/"incidents.json")
```

Then, verbatim in intent:
1. `pageIndicator = StatusIndicator(pageIndicator: status?.status.indicator)`
2. `components = ComponentMatcher.resolve(definition, against: payload)` — carrying the `claimed` set
3. incidents normalised, `affectsWatched` computed against the matched component names
4. `pruneIncidents` → 10 most recent, 14-day window
5. roll-up from watched components; **fall back to `pageIndicator` only when `resolvedCount == 0`**

### 4.2 `ComponentMatcher` — ≙ `matchComponent()`

```swift
enum ComponentMatcher {
    /// Exact name first, regex fallback second. `claimed` prevents a loose
    /// pattern from stealing a component an earlier definition already took —
    /// without it, /chatgpt/ matches "Codex in ChatGPT Desktop" for two
    /// different entries and reports the same status under two labels.
    static func match(_ definition: ComponentDefinition,
                      in apiComponents: [APIComponent],
                      claimed: inout Set<String>) -> APIComponent?
}
```

Registry iteration order is significant and must be preserved — it is what decides who claims a contested component.

### 4.3 Google Cloud adapter

Port of `checkGoogleCloudService()`: filter the flat feed by `GOOGLE_AI_KEYWORDS` over a flattened text blob of `external_desc` + `service_name` + `uri` + `affected_products` + `updates`; derive each component's state from the *active* incidents whose text its patterns match; components with no hits are `.operational` but tagged `provenance: .derivedFromIncidents`. The internal `searchText` is never persisted.

### 4.4 Networking

```swift
struct StatusAPIClient: StatusAPIClientProtocol {
    private let session: URLSession = {
        let c = URLSessionConfiguration.ephemeral
        c.timeoutIntervalForRequest = 10           // ≙ fetchTimeout
        c.requestCachePolicy = .reloadIgnoringLocalCacheData   // ≙ cache: 'no-cache'
        c.httpAdditionalHeaders = ["Accept": "application/json",
                                   "User-Agent": "VibeStats/\(version) (macOS)"]
        c.waitsForConnectivity = false             // fail fast; the coordinator owns retry
        return URLSession(configuration: c)
    }()
}
```

**Retry lives here, not around the sweep** — the fix for REVIEW.md §3.2. Up to 2 retries with jittered backoff on `URLError` transients (`.timedOut`, `.networkConnectionLost`, `.cannotConnectToHost`, `.dnsLookupFailed`) and on 5xx. Never on 4xx. Total worst-case time for one endpoint is bounded at ~30 s, well inside the smallest 1-minute interval.

Decoding is lenient by design: unknown JSON keys are ignored, and a malformed member of an array is dropped rather than failing the whole payload — a vendor adding a field must never blank a card.

## 5. Coordination

`MonitorCoordinator` is `@MainActor`, `@Observable`, and owned by the `AppDelegate`. It is what `background.js` would have been if MV3 had let it hold state.

```swift
@MainActor @Observable
final class MonitorCoordinator {
    private(set) var snapshot: Snapshot?
    private(set) var phase: Phase = .idle    // .idle | .checking | .offline | .failed(String)

    func start()                             // ≙ init(): immediate check + arm timer
    func refreshNow(reason: RefreshReason) async
}
```

### 5.1 Scheduling

- A `DispatchSourceTimer` with `leeway` of 10% of the interval — power-friendly, and does not drift the way a re-armed `Timer` does.
- **Not** `Timer.scheduledTimer`: it does not fire while a modal menu tracks, and it silently misses the whole sleep window without telling you.
- Interval changes cancel and re-arm; a check in flight is allowed to finish.

### 5.2 Wake, sleep and network

| Signal | Source | Action |
|---|---|---|
| System wake | `NSWorkspace.shared.notificationCenter` `didWakeNotification` | Cancel the stale timer, check immediately, re-arm |
| Screens wake | `screensDidWakeNotification` | Check if data older than the interval |
| Network satisfied | `NWPathMonitor` transitioning to `.satisfied` | Leave `.offline`, check immediately |
| Network unsatisfied | `NWPathMonitor` | Enter `.offline`, suspend the timer, stop retrying (FR-7) |
| Popover opened | `PopoverController` | Check if data older than 30 s (≙ `STALE_AFTER_MS`) |

This block is the answer to REVIEW.md §5.3 — the extension's most user-visible gap is a laptop reopened after four hours showing four-hour-old green.

### 5.3 Transition diffing → notifications

`TransitionDiff.transitions(from:to:)` is pure Domain code: given two snapshots it returns component-level `StatusTransition` values. **Transitions into or out of `unknown` are excluded** — "we stopped being able to measure this" is not an outage, and announcing it as one would undo the same discipline that stops an unresolved component from being reported as healthy.

`NotificationDispatcher` applies the policy (degradation/recovery switches, minimum severity judged on *where a degradation landed* and *where a recovery came from*, primary-only, quiet hours with a window that may wrap midnight, per-component cooldown keyed `service.component`) and hands the result to a `NotificationPresenting`. That protocol is the seam: `SystemNotificationPresenter` talks to `UNUserNotificationCenter`; tests use a spy, so the whole policy is verified without a permission prompt.

Two behaviours worth naming:

- **Grouping.** Three or more transitions in one service collapse into a single notification. A service losing six components should interrupt you once, not six times.
- **Lazy authorization.** Permission is requested the first time something would actually be announced — not at launch, which is the behaviour that gets apps quit on day one. A refusal is remembered, so the app stops asking.

The dispatcher also drops the first snapshot after launch outright. `previous` is whatever was on disk, which may be hours stale, so diffing against it would produce a burst of notifications about things that resolved while the machine was asleep (FR-23).

### 5.4 Persistence

```
~/Library/Application Support/VibeStats/
    snapshot.json      last Snapshot — restored at launch so the popover is never empty
    history.jsonl      append-only samples, one line per check, pruned to 7 days
~/Library/Preferences/com.todddube.VibeStats.plist   settings
```

`SnapshotStore` is an actor performing atomic writes (write to `.tmp`, `replaceItemAt`). A corrupt snapshot is discarded, not fatal — the app starts empty and checks.

`HistoryLog` appends `{ t, service, indicator }` per service per check. At ~6 lines every 5 minutes that is ~12k lines/week, a few hundred KB — pruned on launch and daily. This feeds the sparklines (FR-20).

## 6. Presentation

`PopoverView` observes the coordinator directly; there is no second view-model layer duplicating snapshot fields. Purely derived display values (relative times, sparkline paths, chip text) are computed in small `struct` view-models that take a `ServiceSnapshot` and expose formatted strings — testable, and free of `Date.now` at render time (an injected clock keeps the tests stable).

The popover is a pure renderer, exactly as `popup.js` is: it never touches `StatusEngine`. Its only mutating action is asking the coordinator to refresh.

Layout, tokens, and animation are specified in [DESIGN.md](DESIGN.md).

## 8. Concurrency contract

Swift 6.2's `-default-isolation MainActor` means types are `@MainActor` unless stated otherwise — the annotations below are therefore mostly about what is *not* on the main actor.

| Type | Isolation |
|---|---|
| `ServiceRegistry`, all Domain types | `Sendable` value types, no isolation |
| `StatusEngine`, `StatusAPIClient`, `SnapshotStore`, `HistoryLog` | `actor` |
| `MonitorCoordinator`, `StatusItemController`, `PopoverController`, all views | `@MainActor` |
| `NWPathMonitor` / `NSWorkspace` callbacks | Hop to `@MainActor` immediately; never touch state on their own queues |

Strict concurrency is complete and language mode is 6. Nothing is `@unchecked Sendable`. Engine and infrastructure types opt out of the main actor explicitly (`nonisolated` / `actor`), so the isolation of every type is visible at its declaration. Every `await` in the coordinator is bounded by either the session timeout or an explicit `withTimeout` wrapper (the lesson from REVIEW.md §3.3).

## 9. Error taxonomy

| Case | Presentation |
|---|---|
| `.offline` | Dedicated offline banner + hollow glyph. No retries, no `unknown` cascade |
| `.timeout(service)` | That card only → `unknown`, with "timed out" in its diagnostics row |
| `.http(status, service)` | That card → `unknown`, status code shown |
| `.decode(service)` | That card → `unknown`, "unexpected response format" — the signal a vendor changed shape |
| `.unresolvedComponents(n)` | Card shows "n of m components unresolved"; the app does **not** claim operational (REVIEW.md §3.1) |
| Total failure | Combined `unknown`, banner "Unable to check status", never the vibing string |

## 10. Testing

| Layer | Approach |
|---|---|
| Domain | Pure unit tests: mapping tables, `RollUp` (including the all-unknown and mixed-unknown cases), `matchComponent` claimed-set stealing, `pruneIncidents` boundaries |
| Engine | `StatusAPIClientProtocol` stub over **recorded fixtures** in `Tests/Fixtures/` — a real capture of each of the four vendors, plus hand-mutated variants: page-major/components-green, renamed component, empty payload, malformed JSON, 500, timeout |
| Registry parity | Decode a JSON export of `services.js` and assert equality with the Swift registry (specs.md §7.5) |
| Pattern safety | Assert no fallback pattern matches more than one component in the live payloads (REVIEW.md §3.6) |
| Coordination | Injected `Clock` + fake wake/network signals; assert timer re-arm, offline suspension, cooldown, and no-notify-on-first-snapshot |
| Presentation | SwiftUI previews for every state × appearance × motion setting; snapshot tests on the icon renderer at 1× and 2× |

A `make fixtures` target re-captures live payloads so drift is a visible diff rather than a mystery.
